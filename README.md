# edge-fleet-orchestrator-go

用本地内存与本地文件模拟“云端控制面 — 边缘网关 — 设备端”的边缘设备舰队编排系统，
覆盖版本化部署下发、**内容级幂等去重**、断网缓冲与位点续传、状态回流与
**确定性冲突收敛与冲突回报**、多租户/多集群的配额与权限边界。

## 结构

| 包 | 角色 |
|---|---|
| `fleet` | 共享领域类型：`Artifact`/`DeploymentSpec`/`Telemetry`/`ConflictReport`/`Checkpoint`，以及可区分失败原因 `Reason` |
| `controlplane` | 云端控制面（内存实现，互斥锁保证并发确定）：部署、两层幂等、回滚、配额、遥测汇聚与冲突裁决 |
| `edge` | 边缘侧：`Gateway`（断网缓冲/重连续传，持有租户+集群身份）、`Store`（JSON 落盘 + 原子改名）、`Device`（设备端代理） |

## 身份与作用域

设备身份是 **(租户 TenantID, 集群 ClusterID, 设备 DeviceID) 三元组**：

- 同租户、不同集群下的同名设备是两台独立设备，状态、历史、幂等、冲突互不可见；
- 设备 ID 全局归属于一个租户：跨租户访问返回 `FORBIDDEN`，与“资源不存在”
  （`NOT_FOUND`，含“本租户别的集群里有同名设备、但本集群没有”）可明确区分。

## 部署版本与回滚语义

- **版本格式**：制品版本必须匹配 `vMAJOR.MINOR.PATCH`，否则拒绝并返回 `INVALID_VERSION`。
- **兼容性校验**：制品的 OS/架构、大小上限、所需特性必须与设备 `Capabilities` 匹配，否则返回 `INCOMPATIBLE`。
- **两层幂等**（作用域均为同一租户+同一集群下的同一台设备）：
  1. **请求级幂等键**：`DeploymentSpec.IdempotencyKey` 相同的重放直接返回首次记录（同一 `Seq`）。
  2. **内容级幂等**（新增）：不带标识、标识缺失或重试链路把标识换掉都没关系——只要下发
     **内容指纹**（版本 + OS/架构/制品大小 + 依赖特性集合；特性按集合语义参与摘要，书写顺序不影响）
     与该设备历史上某次生效的内容一致，就返回**第一次生效的那条记录**：
     - 版本历史不会变长；
     - 不消耗部署额度（`DeploymentCount` 不增长）；
     - 当前版本会指向该内容（因此从新版本再次下发旧内容，版本会正确“回到”旧内容）。
- **什么才算一次新部署**：只有该设备从未生效过的内容（版本变了，或任一制品属性变了）才追加
  `DeploymentRecord`（全局单调 `Seq`）并消耗一次部署额度。
- **内容幂等的边界**：判定**不跨租户、不跨集群、不跨设备**。不同租户下的同名设备、或同租户不同
  集群下的设备，即使规格逐字节相同，也各自独立生效、各自计数，不会互相顶掉。幂等键同样不跨作用域。
- **回滚**：`Rollback(tenant, cluster, device, version)` 在历史中查找目标版本并复用当时的完整 Spec：
  - 当前生效内容已与目标一致时（含对同一目标的**重复回滚**），原样返回当前生效记录，
    **不新增历史、不多占额度**；
  - 内容确实发生切换时，产生一条 `RollbackOf=目标版本` 的新记录并消耗一次额度；
  - 把与某历史版本内容一致的规格再 `Deploy` 一次，同样命中首次记录、不重复记录；
  - 目标版本不在历史中返回 `NOT_FOUND`，无任何副作用。
- **失败不留痕**：被拒请求（`INVALID_VERSION` / `INCOMPATIBLE` / `FORBIDDEN` / `QUOTA_EXCEEDED`）
  在任何写入与配额扣减**之前**被拒绝：不改历史、不改当前版本、不消耗额度，且四种理由可分别识别。

## 同步与冲突处理规则

- **位点（Seq）**：设备端 `Emit` 产生单调递增位点；网关 `Report` 先写本地 `Store` 再尝试上传，
  断网期间数据只留在本地缓冲，不会丢失。遥测的租户/集群身份由网关统一填充。
- **续传**：重连后 `Sync` 从本地 `Checkpoint`（已确认的最大连续位点）之后开始上传；
  控制面确认后网关 `Ack` 推进位点并清理已确认缓冲。
- **去重**：控制面按 `(租户,集群,设备, Seq)` 去重，重复上报不重复生效，且重复批次仍返回当前确认位点。
- **乱序容忍**：位点可乱序到达；确认位点只按“连续”推进。
- **冲突收敛**（同一租户+集群下同一台设备、同一个键）：
  - **位点不同**：位点大者胜，较低位点的值过期、不覆盖（与到达顺序无关），属于正常的版本推进，
    不记为冲突；
  - **位点相同但值不同**（多路网关/多条上行通道上报同一位置）：采用**纯内容裁决**——
    取值**字典序最大者**为采纳值。结果只由上报内容本身决定，与谁先到、批次如何切分、
    并发多少路、重跑多少遍完全无关。
- **冲突回报（不静默淘汰）**：同位点的每个分歧位置产生一条 `ConflictReport`，含
  采纳值 `Winner`、被淘汰值列表 `Losers`（字典序升序）、裁决规则码
  `SAME_SEQ_DISTINCT_VALUES: lexicographically greatest value wins`。
  - `Ingest` 返回本批次新触发/更新的报告；`Conflicts(tenant, cluster, device)` 可随时查询
    设备上全部冲突报告（按键、位点升序），用于解释“最终这个值是怎么来的”；
  - 后续又到新候选值时，报告会按同一规则重算（采纳值可能被改写）；完全相同内容的重放是幂等的，
    报告不重复、结论不变。
- **重启恢复**：`Store` 每次变更原子落盘（临时文件 + rename）；进程重启后用同一路径
  `OpenStore` 即可恢复缓冲与位点，续传不丢不重。

## 配额与权限边界

- **租户隔离**：设备注册时建立全局 `deviceID -> tenantID` 索引；跨租户访问设备返回 `FORBIDDEN`，
  与资源不存在（`NOT_FOUND`）可区分；同租户跨集群的同名设备按三元组视为不同设备。
- **配额**：`Quota{MaxDevices, MaxDeployments}` 按租户计；只有真正生效的新内容/真实回滚切换才
  消耗 `MaxDeployments`，幂等命中与被拒请求都不消耗。`DeploymentCount(tenant)` 可读取已用量。
- **失败原因**：所有领域错误携带 `fleet.Reason`，用 `fleet.ReasonOf(err)` 提取，取值：
  `INVALID_VERSION` / `INCOMPATIBLE` / `NOT_FOUND` / `FORBIDDEN` / `QUOTA_EXCEEDED` 等。
- **并发确定性**：控制面全部状态变更在单互斥锁下完成；冲突裁决是值的纯函数，
  同一组输入在任何调度/切批/重放下得到逐字节一致的终值与冲突报告。

## 本地验证

```bash
go build ./...
go test ./...                       # 单测日志打印输入与判定依据（go test -v 可见）
go test -race -count=10 ./...       # 竞态检测 + 反复多次运行验证结论稳定
```

测试覆盖（含本次新增）：

- 部署：请求键幂等；**无键/换键重试的内容级幂等**；版本/大小/特性变化才算新部署；
  特性集合乱序去重；旧内容再次下发命中首次记录；
- **作用域**：同租户跨集群同名设备、跨租户设备各自独立生效；跨集群 `NOT_FOUND` 与跨租户
  `FORBIDDEN` 可区分；
- 回滚：可复现回滚、**重复回滚只生效一次**、前滚后再回滚、历史内容再下发去重、回滚未知版本无副作用；
- **失败路径**：非法版本/不兼容/超配额/无权限四种拒绝不改动历史、当前版本与额度；
- 遥测：断网缓冲与重连续传、重复与乱序上报、进程重启恢复；
- **冲突**：同位点多值在不同到达顺序、不同批次切分、多轮并发下收敛一致；晚到候选值改写裁决；
  被淘汰值进入 `ConflictReport`；不同位点不误报冲突；冲突状态按集群隔离。

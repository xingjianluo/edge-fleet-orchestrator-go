# edge-fleet-orchestrator-go

用本地内存与本地文件模拟“云端控制面 — 边缘网关 — 设备端”的边缘设备舰队编排系统，
覆盖版本化部署下发、断网缓冲与位点续传、状态回流与冲突收敛、多租户/多集群的配额与权限边界。

## 结构

| 包 | 角色 |
|---|---|
| `fleet` | 共享领域类型：`Artifact`/`DeploymentSpec`/`Telemetry`/`Checkpoint`，以及可区分失败原因 `Reason` |
| `controlplane` | 云端控制面（内存实现，互斥锁保证并发确定）：部署、幂等、回滚、配额、遥测汇聚 |
| `edge` | 边缘侧：`Gateway`（断网缓冲/重连续传）、`Store`（JSON 落盘 + 原子改名）、`Device`（设备端代理） |

## 部署版本与回滚语义

- **版本格式**：制品版本必须匹配 `vMAJOR.MINOR.PATCH`，否则拒绝并返回 `INVALID_VERSION`。
- **兼容性校验**：制品的 OS/架构、大小上限、所需特性必须与设备 `Capabilities` 匹配，否则返回 `INCOMPATIBLE`。
  特性按**集合**比较，依赖特性的书写顺序不影响判定。
- **设备的有效标识是 (租户, 集群, 设备ID)**：同租户不同集群下的同名设备各自独立、互不顶掉；
  不同租户复用同名设备一律 `FORBIDDEN`。所有按设备的操作（`Deploy`/`Rollback`/`State`/
  `History`/`Conflicts`/`CurrentVersion`）都接受 `clusterID` 参数；当租户内该 `deviceID`
  唯一时允许留空回退，一旦同名设备分布在多个集群又未指定集群，返回 `NOT_FOUND` 并提示需指定集群。
- **两层幂等下发**（重复请求都不追加历史、不推进/切换版本、不消耗部署额度）：
  1. **显式幂等键**：`DeploymentSpec.IdempotencyKey` 相同的重复下发返回该请求**第一次**的
     `DeploymentRecord`（同一 `Seq`，标准请求级幂等语义）。
  2. **内容级幂等**：在同一 (租户, 集群, 设备) 上，只要下发**内容**与此前生效过的某条完全一致
     （版本、OS、架构、制品大小、依赖特性集合均相同），无论是否带标识、标识是否被重试链路换掉、
     并发多少路、重复多少次，本次都是**空操作**：设备保持当前实际生效版本不变。
     返回值始终是设备**当前实际生效**的那一条记录（历史末条，其版本 == `CurrentVersion`），
     而不是该内容第一次生效时的旧记录——因此“把一个和历史版本内容完全一致的下发再提交一次”时，
     返回结果与设备真实状态严格一致，不会出现返回旧记录、设备却跑着新版本的错位。
     若需要把当前版本真正切回某个历史版本，应显式调用 `Rollback`。
     只有内容真正变化才算一次新部署。
     内容指纹不含租户/集群/设备/幂等键，作用域完全由 (租户, 集群, 设备) 限定；
     即使配额已耗尽，重复内容仍允许成功（幂等不占额度）。
- **历史与回滚**：每次成功的“真正变化”追加一条 `DeploymentRecord`（全局单调 `Seq`）。
  `Rollback(tenant, cluster, device, version)` 显式指定集群，在**该设备**历史中查找目标版本，
  **复用当时记录的完整 Spec** 生成新记录（`RollbackOf` 标记目标版本），只影响该集群上的这台设备，
  其他集群的同名设备完全不受影响。语义：
  - 第一次回滚到某个版本（当前不是它）：这是一次真正的版本切换，追加回滚记录、计一次额度；
  - 对同一目标重复回滚、或当前已是该版本时再回滚：空操作，返回**当前实际生效**的记录，
    不多出历史记录、不占额度，返回与真实状态一致；
  - 目标版本从未在该设备历史中出现返回 `NOT_FOUND`（回滚不会“复活”从没部署过的内容）。
  - 配额已耗尽时：空操作类重复回滚仍成功；需要真正切换版本的回滚被 `QUOTA_EXCEEDED` 拒绝。
- **失败请求无副作用**：`INVALID_VERSION` / `INCOMPATIBLE` / `FORBIDDEN` / `QUOTA_EXCEEDED` /
  回滚目标 `NOT_FOUND` 这些拒绝都发生在任何落库与计费之前——不改历史、不改当前版本、不消耗额度，
  各原因可明确区分。

## 同步与冲突处理规则

- **位点（Seq）**：设备端 `Emit` 产生单调递增位点；网关 `Report` 先写本地 `Store` 再尝试上传，
  断网期间数据只留在本地缓冲，不会丢失。
- **续传**：重连后 `Sync` 从本地 `Checkpoint`（已确认的最大连续位点）之后开始上传；
  控制面确认后网关 `Ack` 推进位点并清理已确认缓冲。
- **去重**：控制面按 `(ClusterID, DeviceID, Key, Seq, Value)` 对上报内容去重（含通道换名重发）；
  完全相同的内容重复到达（含整批重放）不重复生效，也不会重复产生冲突报告。
- **乱序容忍**：位点可乱序到达；确认位点只按“连续”推进。
- **冲突确定性收敛（规则更新）**：同一 `(设备, Key)` 状态位置的最终值**只由上报内容决定**：
  先比 `Seq`，位点大者胜；**位点相同则比 `Value`，取值字典序较大者**。
  控制面按 `(Key -> Seq -> Value)` 全量保留收到的内容，每次都从全量内容**重算规范化结论**，
  而不是“先到者占位”。因此无论这些值以什么顺序到达、分几批、并发多少路、重跑多少遍：
  最终值一致，每个被淘汰值对应的败方记录一致，记录里的判定依据逐字一致。
  若一个位置在最高位点有两个以上不同值（如 `alpha`/`beta`/`gamma`），胜方为字典序最大的
  `gamma`，`alpha`、`beta` 各产生一条败方记录；“值尚未到齐”时出现的临时淘汰
  （例如先到的 `beta` 一度压过 `alpha`）不会残留在最终结论里——这正是旧实现里
  “换个到达顺序/批次/并发后，被淘汰的记录和判定依据对不上”的根因。
  - “位点不同”被视为正常版本推进（旧值过期），**不算冲突**、不写冲突记录；
  - “同位点但值不同”才是多路网关/多条上行通道的**冲突**：被淘汰的一方不会静默消失，
    控制面通过 `IngestDetailed`（返回本批结束后**规范化成立、批前尚不存在**的败方记录；
    整批一次提交时批内中间态不会出现在回报中）和 `Conflicts(tenant, cluster, device)`
    （累积，按 位置/位点/败方值 规范化排序）返回 `ConflictReport`，记录胜方/败方的值与
    通道来源（`Telemetry.Source`）以及人类可读、逐字稳定的判定依据
    （`Reason=CONFLICT_RESOLVED`），可据此解释最终值的由来；
  - 通道来源仅用于解释，**不参与**胜负判定（同一值的代表来源按内容规范化，先到者无特权）。
- **重启恢复**：`Store` 每次变更原子落盘（临时文件 + rename）；进程重启后用同一路径
  `OpenStore` 即可恢复缓冲与位点，续传不丢不重。

## 多集群接入

- `edge.NewGateway(tenant, cp, store)` 不绑定集群（单集群回退，按设备ID唯一定位）；
- `edge.NewClusterGateway(tenant, cluster, source, cp, store)` 绑定集群与上行通道，
  上报时自动补齐 `ClusterID`/`Source`。多路网关各建一个实例（建议各自独立 `Store` 文件）。

## 配额与权限边界

- **租户隔离**：设备注册时建立 `deviceID -> (tenantID -> clusterID)` 索引；
  跨租户访问设备返回 `FORBIDDEN`，与资源不存在（`NOT_FOUND`）可区分；
  同租户下定位不存在的集群/设备返回 `NOT_FOUND`（多集群同名设备且未指定集群时提示需指定集群），
  回滚与其它按设备操作共用这一定位规则，绝不会因为同名设备误伤另一个集群。
- **配额**：`Quota{MaxDevices, MaxDeployments}` 按租户计；只有“真正变化”的成功部署/回滚才计数，
  重复内容、重复回滚与失败请求都不消耗额度；超限返回 `QUOTA_EXCEEDED`。
  额度耗尽后，重复内容下发与“当前已是目标版本”的重复回滚仍会成功（空操作不占额度），
  但需要真正切换版本的部署/回滚仍被拒绝。
- **失败原因**：所有领域错误携带 `fleet.Reason`，用 `fleet.ReasonOf(err)` 提取，取值：
  `INVALID_VERSION` / `INCOMPATIBLE` / `NOT_FOUND` / `FORBIDDEN` / `QUOTA_EXCEEDED` /
  `CONFLICT_RESOLVED` 等。
- **并发确定性**：控制面全部状态变更在单互斥锁下完成；同一资源的并发更新被串行化，
  且收敛规则只依赖内容，任意调度顺序下结果一致。

## 本地验证

```bash
go build ./...
go test ./...                          # 单测日志打印覆盖的业务、输入与判定依据（go test -v 可见）
go test -race -count=10 ./...          # 竞态检测 + 反复运行验证结论稳定
go test -v ./... -run 'Idempot|Conflict|Rollback|Rejected|Reissue|Repeated'  # 只跑幂等/冲突/回滚场景
```

测试覆盖（均在 `-race` 与反复运行下稳定；日志逐条打印输入与判定依据）：
- 多集群同名设备：分别按集群回滚、只影响目标集群、重复回滚只生效一次、未指定集群时 `NOT_FOUND` 且不误伤
  （`TestRollbackSameNameDevicePerCluster`）；
- 同一位置两个以上不同值：全部到达排列、逐条/分批/随机切分、多路并发 × 多轮、整批重放下，
  最终值、每个败方记录、判定依据逐字一致，且重放不重复回报、不重复记录
  （`TestConflictThreeValuesAllPermutations` / `TestConflictBatchSplittingAndReplay` /
  `TestConflictConcurrentDeterministic`）；
- 历史内容重复下发（带新键/无键）为空操作且返回当前实际生效记录、重复回滚多个目标的一致性、
  回滚到不存在版本 `NOT_FOUND` 且无副作用
  （`TestReissueHistoricalContentKeepsReturnConsistentWithState` /
  `TestRepeatedRollbackConsistent` / `TestFailedRollbackNoSideEffects`）；
- 以及既有的：重试/不带标识/换标识的内容级重复下发、内容指纹各维度、
  按租户与集群的作用域隔离（含跨租户 FORBIDDEN 与 NOT_FOUND 区分）、并发内容幂等、
  同位点两值不同到达顺序/并发/整批重放的确定性收敛与败方冲突回报、
  四类失败请求不留副作用、配额耗尽下幂等仍生效；部署幂等/非法版本/能力不兼容、
  断网缓冲与重连续传、重复与乱序上报、进程重启恢复、并发上报一致性等。
